# Yeelight: сервер, менеджер и локальная библиотека

Проект разделён на три независимых Python-пакета. Сервер не общается с лампами
напрямую: он принимает типизированные команды из браузера и передаёт их
подключённому менеджеру по исходящему WebSocket. Менеджер работает в локальной
сети рядом с лампами и использует общую библиотеку `yeelight-logic`.

```text
браузер  ──HTTP/WS──▶  yeelight-server  ◀──исходящий WebSocket──  yeelight-manager
                                                                       │
                                                                       ▼
                                                              yeelight-logic
                                                                       │
                                                                       ▼
                                                                  лампы Yeelight
```

Такое разделение позволяет держать веб-интерфейс на одном компьютере, а
менеджер — на мини-ПК или ноутбуке в той же сети, что и лампы. Наружу менеджер
не открывает портов: он сам подключается к серверу.

## Пакеты

| Пакет | Где работает | Ответственность |
| --- | --- | --- |
| `yeelight-logic` | везде | LAN-команды, discovery, контроллер, `Bulb`, типизированный dispatcher, miIO-настройка Wi-Fi и LAN Control. |
| `yeelight-manager` | рядом с лампами | Flet-интерфейс, локальный loopback API, мониторинг ламп, спаривание с сервером, WebSocket-ретранслятор. |
| `yeelight-server` | там, где нужен веб-доступ | Пользователи, сессии, CSRF, SQLite, спаривание менеджеров, команды, режимы, аудит и веб-интерфейс. |

Единственная реализация операций с лампами находится в `yeelight-logic`. И
менеджер, и сервер используют один и тот же набор типизированных действий; сервер
не содержит кода, который открывает TCP-соединение с лампой.

## Возможности

- Поиск, добавление, удаление и мониторинг ламп.
- Управление питанием, яркостью, цветом RGB и цветовой температурой.
- Веб-интерфейс для компьютера и телефона.
- Консоль с прежними текстовыми командами: браузер разбирает строку и отправляет
  типизированное действие, произвольные команды на сервер не передаются.
- Циклические режимы и готовые пресеты; режимы хранятся в SQLite и выполняются
  через менеджер.
- Настройка Wi-Fi и LAN Control только локально, с явным подтверждением. Пароль
  Wi-Fi не сохраняется и не логируется.
- Отдельная аутентификация человека (cookie-сессия) и менеджера (одноразовый код
  спаривания и долгоживущий токен).
- Аудит действий без секретов, ограничение размера запросов и rate limit.

## Быстрый старт в Windows

Требуется Python 3.10 или новее.

```powershell
tools\setup.bat
```

Скрипт создаёт `.venv`, устанавливает три пакета в editable-режиме и создаёт
`.env` на основе `.env.example`. Если база ещё не содержит пользователей, он
генерирует пароль администратора и записывает его в `.env` (в консоль пароль не
выводится).

Запуск сервера:

```powershell
start-server.bat
```

Откройте `http://127.0.0.1:8000`, войдите под `YEELIGHT_SERVER_ADMIN_USER`
(по умолчанию `admin`) и паролем из `.env`.

Затем:

1. На странице «Менеджеры» создайте одноразовый код (действует 10 минут).
2. На машине с лампами выполните `start-manager.bat --pair <КОД>`.
3. Запустите `start-manager.bat` — откроется окно менеджера, и он подключится к
   серверу.
4. В веб-интерфейсе нажмите «Найти лампы» или добавьте IP вручную.
5. Управляйте лампами на странице «Лампы» или через «Консоль».

`start-all.bat` запускает сервер и менеджер в отдельных окнах и открывает
браузер. Для машины без графического интерфейса используйте
`start-manager.bat --no-ui`.

## Ручная установка

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e packages\yeelight-logic
.\.venv\Scripts\python.exe -m pip install -e packages\yeelight-manager
.\.venv\Scripts\python.exe -m pip install -e packages\yeelight-server
Copy-Item .env.example .env
```

Заполните `YEELIGHT_SERVER_ADMIN_PASSWORD` в `.env` (не менее 8 символов) до
первого запуска. После создания базы пароль хранится только как scrypt-хеш, а
значение из `.env` при следующих запусках не используется. Сменить пароль можно
командой:

```powershell
.\.venv\Scripts\python.exe -m yeelight_server --set-password
```

Запуск без скриптов:

```powershell
.\.venv\Scripts\python.exe -m yeelight_server
.\.venv\Scripts\python.exe -m yeelight_manager
```

Все команды выполняйте из корня репозитория: относительные пути (`data/`,
`.env`) считаются от текущего каталога.

## Менеджер

Менеджер — отдельное приложение. Оно хранит состояние в домашнем каталоге
пользователя:

- Windows: `%LOCALAPPDATA%\YeelightManager`;
- Linux: `$XDG_DATA_HOME/YeelightManager` или `~/.local/share/YeelightManager`;
- macOS: `~/Library/Application Support/YeelightManager`.

В каталоге находятся `state.json`, `bulbs.json` и `token.bin`. Токен менеджера
на Windows шифруется DPAPI, на Unix записывается в файл с правами `0600` внутри
каталога `0700`. В `state.json` токена нет.

Основные команды:

```powershell
start-manager.bat                     # окно + локальный API + WebSocket
start-manager.bat --no-ui             # без окна, удобно для мини-ПК
start-manager.bat --no-local-api      # без локального HTTP API
start-manager.bat --pair <КОД>        # спаривание и выход
start-manager.bat --unpair            # удалить локальный токен
start-manager.bat --status            # снимок состояния в JSON
start-manager.bat --discover          # поиск ламп и вывод результата
start-manager.bat --server http://192.168.1.10:8000
```

Локальный API менеджера слушает только loopback (`127.0.0.1:8765` по
умолчанию). Изменяющие запросы требуют заголовок `X-Yeelight-Manager: 1`;
запросы с чужим `Origin` отклоняются. Настройка Wi-Fi и LAN Control требует
дополнительно `"confirm": true` в теле запроса.

Основные локальные маршруты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка процесса. |
| GET | `/api/status` | Состояние менеджера, агента и ламп. |
| GET | `/api/lamps` | Кэш состояний ламп. |
| POST | `/api/lamps/discover` | Поиск ламп. |
| POST | `/api/lamps` | Добавить лампу по IP. |
| DELETE | `/api/lamps/{ip}` | Удалить лампу. |
| POST | `/api/lamps/{ip}/command` | Типизированное действие. |
| POST | `/api/provisioning/wifi` | Настройка Wi-Fi (только локально). |
| POST | `/api/provisioning/lan-control` | Включение LAN Control (только локально). |
| POST | `/api/pair`, `/api/unpair`, `/api/reconnect` | Спаривание и переподключение. |

## Wi-Fi и LAN Control

Эти операции намеренно отсутствуют в API сервера. Они выполняются в окне
менеджера или через его локальный API и требуют отдельного подтверждения.

- Поддерживаемая модель экспериментальной настройки Wi-Fi:
  `yeelink.light.color1`.
- Пароль Wi-Fi используется только в памяти для одного зашифрованного miIO
  запроса и не сохраняется, не возвращается и не пишется в логи.
- Успешный ответ miIO означает «запрос доставлен», но не доказывает подключение
  к сети. После настройки подключите компьютер к целевой сети и выполните поиск.
- LAN Control можно попробовать включить отдельно для уже доступной лампы.
  Ответ устройства также не доказывает, что TCP 55443 и SSDP уже работают.
- Для остальных моделей используйте официальное приложение Yeelight.

## Веб-интерфейс

- `/` — обзор, состояние менеджеров и ламп.
- `/bulbs` — список ламп и управление.
- `/modes` — режимы и пресеты.
- `/console` — форма команд и история.
- `/setup` — спаривание менеджеров и диагностика.
- `/help` — встроенная инструкция.
- `/login` — вход.

Консоль принимает прежние команды:

```text
discover
list
add 192.168.1.45
remove 192.168.1.45
status 192.168.1.45
on 192.168.1.45
off 192.168.1.45
toggle 192.168.1.45
brightness 192.168.1.45 60
color 192.168.1.45 51 170 255
color 192.168.1.45 #33aaff
temp 192.168.1.45 4000
```

Браузер преобразует их в `power`, `brightness`, `color`, `color_temperature`,
`status`, `discover`, `add`, `remove` или `list`. Сервер принимает только этот
закрытый набор; произвольные строки и shell-подобные команды отклоняются.

## Режимы

Режим — это последовательность задач и задержка между ними. Поддерживаются
действия `on`, `off`, `toggle`, `status`, `brightness`, `color`, `temp`.
Режимы хранятся в SQLite и запускаются для выбранного менеджера и IP. Сервер
передаёт каждый шаг как типизированную команду и ждёт результат.

Старый файл `data/modes.json` импортируется один раз при первом запуске, если в
базе ещё нет режимов. После импорта создаётся отметка в `metadata`, поэтому
повторный запуск не дублирует данные.

Прошивка лампы принимает примерно 60 LAN-команд в минуту. Менеджер и библиотека
соблюдают безопасный интервал между командами одной лампы. После десяти ошибок
подряд режим останавливается и сохраняет причину в `last_error`.

## Настройки

Параметры читаются из `.env` в корне проекта и из переменных окружения.
Переменные окружения имеют приоритет. После изменения `.env` перезапустите
процесс.

| --- | --- | --- |

| `YEELIGHT_SERVER_PORT` | `8000` | Порт. |
| `YEELIGHT_SERVER_DB` | `data/server.db` | Файл SQLite. |

| `YEELIGHT_SERVER_SESSION_TTL_SECONDS` | `43200` | Время жизни сессии. |
| `YEELIGHT_SERVER_SECURE_COOKIES` | `false` | Флаг `Secure` у cookie; включайте при HTTPS. |
| `YEELIGHT_SERVER_TLS_CERT`, `YEELIGHT_SERVER_TLS_KEY` | пусто | Пара файлов TLS для uvicorn. |

## Безопасность

- Пароли пользователей хранятся как scrypt-хеши. Сессия — непрозрачная
  `HttpOnly` cookie `yl_session`; изменяющие запросы требуют `X-CSRF-Token`.
- Токен менеджера имеет префикс `ylm_`, на сервере хранится только его SHA-256
  хеш. Токен передаётся один раз при спаривании.
- Коды спаривания одноразовые, живут 10 минут; попытки спаривания ограничены.
- Сервер не принимает Wi-Fi-пароль и не имеет маршрутов настройки ламп.
- Пароль Wi-Fi не сохраняется. Токен менеджера не попадает в `state.json`,
  ответы API и логи.
- Включены ограничение размера тела запроса (256 КиБ), security headers и
  rate limit для входа, спаривания и команд.
- Не открывайте сервер в публичный интернет. Для доступа из LAN используйте
  HTTPS через reverse proxy и `YEELIGHT_SERVER_SECURE_COOKIES=true`.

## Проверки

Обычные тесты не требуют ламп, сети или запущенного сервера:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Аппаратные и end-to-end проверки включаются только переменными окружения.
Подробности — в `tests/README.md`.

## Структура репозитория

```text
packages/
  yeelight-logic/   # библиотека и протокол
  yeelight-manager/ # Flet-приложение, локальный API, WebSocket-агент
  yeelight-server/  # FastAPI, SQLite, шаблоны и статические файлы
tests/              # unittest-наборы
tools/              # setup и скрипты запуска
data/               # локальная база и старые режимы (не коммитятся)
```

## Ограничения

- SQLite и rate limit рассчитаны на один процесс сервера. Для нескольких
  экземпляров нужен общий store и внешняя БД.
- Экспериментальная настройка Wi-Fi поддерживает только
  `yeelink.light.color1`.
- Ответ miIO не является подтверждением сетевого подключения или LAN Control.
- Проект не заменяет официальное приложение для первоначальной настройки всех
  моделей и не обходит ограничения прошивки.
