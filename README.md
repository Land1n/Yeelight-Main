# Yeelight

Проект разделен на четыре пакета, которые можно будет вынести в отдельные
репозитории `Yeelight-Main`, `Yeelight-Network`, `Yeelight-App` и
`Yeelight-Logic`. Network, App и Logic подключены к Main как Git-подмодули.

Клонируйте Main вместе с компонентами:

```powershell
git clone --recurse-submodules https://github.com/Land1n/Yeelight-Main.git
```

Если Main уже клонирован без компонентов, выполните
`git submodule update --init --recursive` из его папки.

## Возможности

- Сервер FastAPI принимает команды и управляет лампами Yeelight в локальной сети.
- Веб-клиент обслуживается самим сервером и работает в браузере Windows,
  Android и других устройств.
- Отдельное приложение Flet можно запустить на Windows или собрать для Android.
- Logic изолирует протокол ламп от сетевого API. Новые типы устройств и
  транспортов можно добавлять отдельными адаптерами.
- Список известных ламп хранится в памяти сервера и настраивается через
  `YEELIGHT_BULBS`.

Лампы Yeelight обычно управляются по Wi-Fi через LAN-протокол. Подключение USB
не является универсальным способом управления ими и здесь не эмулируется.

## Установка

Нужен Python 3.10 или новее.

Самый простой способ для Windows — запустить `setup.bat` двойным щелчком из
папки проекта. Скрипт инициализирует подмодули, создаст `.venv`, скопирует
`.env.example` в `.env`, если файла ещё нет, и установит зависимости.
Дождитесь сообщения об успешной установке и нажмите клавишу, чтобы закрыть
окно.

Те же действия вручную в PowerShell:

```powershell
git submodule update --init --recursive
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell запрещает активировать виртуальное окружение, не меняйте
политику безопасности: используйте Python напрямую как
`.\.venv\Scripts\python.exe` или запускайте `.bat`-скрипты проекта.

Настройки сервера и клиента хранятся в корневом `.env`. Скрипт `setup.bat`
создаёт его из шаблона автоматически; вручную файл можно создать или
восстановить так:

```powershell
Copy-Item .env.example .env
```

Переменные:

| Переменная | Назначение |
| --- | --- |
| `YEELIGHT_HOST` | Адрес прослушивания сервера; для доступа телефону установите `0.0.0.0` |
| `YEELIGHT_PORT` | Порт сервера, по умолчанию `8000` |
| `YEELIGHT_API_TOKEN` | Секретный токен; обязателен при `YEELIGHT_HOST=0.0.0.0` |
| `YEELIGHT_BULBS` | Необязательные IP ламп через запятую |
| `YEELIGHT_SERVER_URL` | Адрес API для Flet-клиента; на телефоне замените localhost на IP компьютера |
| `YEELIGHT_POLL_INTERVAL_SECONDS` | Интервал проверки ламп в секундах (по умолчанию `10`) |
| `YEELIGHT_UNRESPONSIVE_TIMEOUT_SECONDS` | Сколько секунд лампа может не отвечать до удаления из списка (по умолчанию `60`) |
| `YEELIGHT_MODES_FILE` | Файл сохранения циклических режимов (по умолчанию `data/modes.json`) |

`.env` исключён из Git; не помещайте в него пароли или токены, которыми нельзя
делиться, в `.env.example`.

## Запуск

После изменения `.env` перезапускать сервер обязательно. Запустите сервер:

```powershell
python -m yeelight_network.server
```

В Windows можно запускать приложения двойным щелчком:

- `setup.bat` — создать `.venv`, установить зависимости и при необходимости
  создать `.env`;
- `start-server.bat` — запустить сервер;
- `start-app.bat` — запустить Flet-клиент;
- `start-all.bat` — открыть сервер и Flet-клиент в отдельных окнах.
- `configure-phone.bat` — включить доступ сервера из локальной сети и создать
  случайный API-токен, если он ещё не задан.

После первого запуска `setup.bat` обычно достаточно использовать
`start-all.bat`.

Для управления с телефона сначала запустите `configure-phone.bat`. Скрипт
настроит сервер на приём подключений из локальной сети, создаст API-токен и
покажет LAN-адреса компьютера. Если адресов несколько, выберите тот, который
находится в одной сети с телефоном. В окне сервера адреса также выводятся при
старте. Разрешайте подключения Python только в частной сети Windows Firewall.
Перезапустите сервер после изменения конфигурации.

Затем откройте Flet-клиент: введите показанный адрес и значение
`YEELIGHT_API_TOKEN` из `.env`, нажмите «Сохранить и подключиться». Приложение
проверит соединение и сохранит адрес с токеном в локальном хранилище устройства
для последующих запусков. Токен хранится в настройках приложения и не является
зашифрованным хранилищем секретов; используйте его только в доверенной сети.
Если компьютер получил новый LAN-IP, измените адрес и сохраните подключение
повторно.

Веб-интерфейс доступен по адресу `http://127.0.0.1:8000`. Отдельный
настольный/мобильный клиент Flet запускается командой:

```powershell
python -m yeelight_app
```

Команда `python -m yeelight_app` запускает нативный клиент Flet. На телефоне
и компьютер-сервер должны быть в одной Wi-Fi сети. Адрес `127.0.0.1` на
телефоне означает сам телефон, а не компьютер.

Для сборки Android-приложения установите Flutter и Android SDK, затем из
корневой папки проекта выполните:

```powershell
.\.venv\Scripts\flet.exe build apk --module-name main
```

Flet соберет APK, который можно установить на телефон для тестирования.
В приложении укажите LAN-IP компьютера с сервером и API-токен, если он задан.

Для сборки Windows-клиента (требуется установленный Visual Studio с workload
**Desktop development with C++**) используйте:

```powershell
.\.venv\Scripts\flet.exe build windows --module-name main
```

Flet Web-сборку можно получить так:

```powershell
.\.venv\Scripts\flet.exe build web --module-name main
```

Выходные файлы находятся в `build\apk`, `build\windows` или `build\web`.
Веб-сборка Flet-клиента является отдельным приложением; обычный браузерный
интерфейс управления уже раздаёт сервер Yeelight.

### Структура проекта

- `yeelight_logic/controller.py` — команды и непосредственное управление лампами.
- `yeelight_network/api.py` — HTTP API, мониторинг ламп и циклические режимы.
- `yeelight_network/server.py` — конфигурация и запуск сервера.
- `yeelight_app/__main__.py` — нативный интерфейс Flet.
- `yeelight_app/api_client.py` — HTTP-клиент приложения Flet.
- `yeelight_app/widgets.py` — виджеты Flet для ламп.
- `yeelight_app/static/index.html` — разметка браузерного клиента.
- `yeelight_app/static/css/app.css` — стили браузерного клиента.
- `yeelight_app/static/js/` — отдельные ES-модули API, ламп, режимов и редактора.

Браузерные CSS/JS-файлы раздаются сервером из `/static/` и включены в пакет
приложения, поэтому они доступны как из исходного репозитория, так и после
установки wheel-пакета.

По умолчанию сервер доступен только локально (`127.0.0.1`). Чтобы подключить
другие устройства, задайте в `.env` `YEELIGHT_HOST=0.0.0.0` и длинный случайный
`YEELIGHT_API_TOKEN`. Клиент подставляет этот токен из `.env`; в веб-клиенте
токен вводится вручную и хранится только в сессии вкладки. Разрешите серверу
подключения только из доверенной сети через Windows Firewall. Не открывайте
его в интернет: HTTP не шифрует трафик.

Для Android откройте в браузере телефона адрес сервера, доступный устройству,
например `http://192.168.1.10:8000`.

## Команды консоли

```text
discover                         найти Yeelight в сети
list                             показать известные лампы
add 192.168.1.45                 добавить лампу по IP
remove 192.168.1.45              удалить лампу из списка
status 192.168.1.45              получить свойства лампы
on 192.168.1.45                  включить
off 192.168.1.45                 выключить
toggle 192.168.1.45              переключить состояние
brightness 192.168.1.45 60       установить яркость (1-100)
color 192.168.1.45 51 170 255    установить RGB-цвет (каналы 0-255)
color 192.168.1.45 #33aaff       установить RGB-цвет в hex-формате
temp 192.168.1.45 4000           установить цветовую температуру (1700-6500 K)
help                             показать справку в Flet-клиенте
clear                            очистить консоль Flet-клиента
```

`help` и `clear` обрабатываются локально и не отправляются серверу.

## Подробное руководство: первый запуск и подключение

### Как устроена программа

В проекте есть две части:

1. **Сервер** запускается на компьютере. Он принимает запросы по локальной
   сети, находит Yeelight и отправляет им команды.
2. **Клиент** — это Flet-приложение на компьютере или Android либо веб-страница
   в браузере. Клиент подключается к серверу и передаёт ему команды.

Лампа, компьютер и телефон должны быть доступны друг другу по сети. Подключать
лампу USB-кабелем не нужно: используемый здесь способ управления Yeelight —
Wi-Fi/LAN.

### Вариант A: попробовать всё на одном компьютере

1. Убедитесь, что Python установлен и первый запуск `setup.bat` завершился
   успешно.
2. Запустите `start-all.bat`. Откроются два окна: сервер и Flet-клиент.
   Не закрывайте окно сервера, пока работаете с лампами.
3. В клиенте оставьте адрес `http://127.0.0.1:8000`. Если токен не задан,
   поле токена можно оставить пустым.
4. Введите `discover` в консоль и нажмите «Выполнить». Команда сканирует
   локальную сеть; найденные лампы должны появиться в списке.
5. Если сканирование не нашло лампу, но известен её IP-адрес, введите, например,
   `add 192.168.1.45`, затем `list` и попробуйте `status 192.168.1.45`.

Для проверки сервера в браузере компьютера откройте
`http://127.0.0.1:8000`. Веб-интерфейс доступен и на телефоне, если настроить
доступ по LAN, как описано ниже.

### Вариант B: подключить телефон к серверу на компьютере

**Шаг 1. Подключите устройства к одной сети.** Компьютер и телефон должны
находиться в одной домашней/рабочей Wi-Fi или LAN-сети. Не используйте
гостевую Wi-Fi-сеть: в ней часто запрещено устройствам обращаться друг к
другу. Отключите на время проверки VPN на телефоне и компьютере, если он
перенаправляет локальный трафик.

**Шаг 2. Настройте сервер для локальной сети.** На компьютере дважды нажмите
`configure-phone.bat`. Скрипт изменит корневой `.env`: установит
`YEELIGHT_HOST=0.0.0.0` и создаст случайный `YEELIGHT_API_TOKEN`, если токен
ещё не был указан. В окне появятся возможные адреса сервера, например
`http://192.168.1.10:8000`.

Если скрипт показал несколько адресов, выберите адрес Wi-Fi/Ethernet-сети,
к которой подключён телефон. Не выбирайте `127.0.0.1`, адрес VPN или
виртуального адаптера. Чтобы проверить IPv4 компьютера вручную, выполните
`ipconfig` в PowerShell и найдите IPv4-адрес активного Wi-Fi/Ethernet-адаптера.

**Шаг 3. Разрешите доступ в брандмауэре.** Если Windows покажет запрос
брандмауэра при запуске сервера, разрешите Python только для **частных сетей**
(домашняя доверенная сеть). Не включайте разрешение для публичных сетей.
Если запрос не появился и телефон не соединяется, откройте «Брандмауэр
Защитника Windows» → «Разрешение взаимодействия с приложением» и разрешите
используемый Python для частных сетей. Не отключайте брандмауэр целиком.

**Шаг 4. Запустите сервер и оставьте его работать.** Запустите
`start-server.bat`. В его окне должны появиться LAN-адреса и затем сообщения
Uvicorn о запуске. Не закрывайте это окно. Если после изменения `.env` сервер
уже работал, остановите его `Ctrl+C` и запустите снова: настройки читаются
при запуске.

**Шаг 5. Проверьте связь с телефона.** Откройте браузер на телефоне и введите
адрес сервера целиком, например `http://192.168.1.10:8000` — с `http://` и
портом `:8000`. Должна открыться страница Yeelight. Если страница не
открывается, сначала устраните проблему сети по таблице ниже; установка APK
сама по себе не подключает телефон к серверу.

**Шаг 6. Подключите клиент.** Выберите один из способов:

- **Без установки приложения:** используйте страницу, открытую в браузере.
  В поле «Адрес сервера» укажите тот же адрес. Скопируйте значение
  `YEELIGHT_API_TOKEN` из корневого `.env` в поле токена. Веб-страница
  сохраняет токен только до закрытия вкладки.
- **Нативное Flet-приложение:** установите APK по инструкции ниже, откройте
  приложение и укажите LAN-адрес сервера и токен из `.env`. Нажмите
  «Сохранить и подключиться». При успешной проверке настройки сохранятся на
  устройстве для следующих запусков.

В адресе клиента указывайте только базовый URL, например
`http://192.168.1.10:8000`, без `/api` и без завершающего пути.
`127.0.0.1` и `localhost` на телефоне указывают на сам телефон, а не на
компьютер.

### Установка и сборка Android APK

Для сборки на Windows установите Android Studio с Android SDK. В Android
Studio откройте **SDK Manager** и установите Android SDK Platform, Android
SDK Build-Tools, Android SDK Platform-Tools и Android SDK Command-line Tools
(latest). Примите лицензии Android SDK. Проверить, видит ли Flet инструменты,
можно командой:

```powershell
.\.venv\Scripts\flet.exe doctor
```

Если Android SDK установлен не в стандартную папку, задайте `ANDROID_HOME` и
`ANDROID_SDK_ROOT` равными пути к нему. Например, для стандартного расположения
в текущем окне PowerShell:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
```

Из корня проекта соберите APK:

```powershell
.\.venv\Scripts\flet.exe build apk --module-name main
```

Первая сборка может занять заметное время: Flutter скачает компоненты Android.
Путь к созданному файлу можно найти командой:

```powershell
Get-ChildItem .\build -Recurse -Filter *.apk | Select-Object -ExpandProperty FullName
```

Скопируйте APK на телефон и откройте его. Android может попросить разрешить
установку приложений из используемого источника — выдавайте это разрешение
только для доверенного файла и затем отключите его, если оно больше не нужно.
Либо подключите телефон с включённой USB-отладкой, установите Android
Platform-Tools и выполните `adb install -r "полный\путь\к\файлу.apk"`.

APK — это клиент, а не сервер: сервер должен оставаться запущенным на
компьютере. После установки подключитесь к нему по инструкции выше.

### Команды и обычная работа

В консоль вводится одна команда за раз. Примеры:

```text
help
discover
list
add 192.168.1.45
remove 192.168.1.45
status 192.168.1.45
on 192.168.1.45
off 192.168.1.45
toggle 192.168.1.45
brightness 192.168.1.45 60
color 192.168.1.45 51 170 255
temp 192.168.1.45 4000
clear
```

Сначала выполните `discover` или `add <IP>`, чтобы сервер узнал лампу.
Команды `on`, `off`, `toggle`, `status`, `brightness`, `color` и `temp`
принимают IP-адрес лампы. Яркость задаётся числом от 1 до 100, цвет —
тремя каналами RGB от 0 до 255 (например, `color 192.168.1.45 255 120 0`).
Также поддерживается старый формат цвета `#RRGGBB`. Температура — числом от 1700 до
6500 К. Поддерживаемые лампой диапазоны могут быть уже указанного диапазона.
В веб-клиенте цвет можно выбрать палитрой в меню карточки лампы; в Flet-клиенте
есть набор готовых цветов в меню «Цвет». Индикатор рядом с IP показывает,
отвечает ли лампа; состояние обновляется автоматически.

`list` показывает лампы, известные **текущему процессу сервера**. Добавление
через `add` и результат `discover` хранятся в памяти и сбрасываются после
перезапуска сервера. Чтобы задать фиксированный список адресов постоянно,
перечислите их в `.env` через запятую, например
`YEELIGHT_BULBS=192.168.1.45,192.168.1.46`, и перезапустите сервер.
Для устройств с меняющимся DHCP-адресом настройте резервирование адреса в
роутере.

Сервер периодически проверяет лампы и удаляет их из списка, если они не
отвечают дольше `YEELIGHT_UNRESPONSIVE_TIMEOUT_SECONDS`. Интервал проверки и
таймаут задаются в `.env`; после изменения перезапустите сервер. В веб-клиенте
лампу также можно удалить вручную из меню «Управление». Там же находятся
команды включения, выключения, яркости (ползунок), цвета (палитра) и температуры.
Фоновое обновление обновляет индикаторы связи, не пересоздавая карточки и не
закрывая открытое меню.

### Циклические режимы

В веб-клиенте откройте раздел «Режимы», задайте название и паузу, затем
добавьте задачи кнопкой «Добавить задачу». У каждой задачи выберите действие,
а для настройки цвета, яркости или температуры задайте значение отдельной
палитрой или ползунком с текущим значением. IP в режим не записывается:
выберите лампу из списка непосредственно перед запуском. Запустить или
остановить сохранённый режим можно также из меню «Управление» нужной лампы.
Сохранённые режимы можно изменить кнопкой «Изменить»: задачи и пауза загрузятся
в конструктор, а сохранение перезапишет существующий режим в `data/modes.json`.
Перед редактированием работающий режим нужно остановить. В списке режим
показывается кратко: первое действие → … → последнее действие.

Задачи выполняются по очереди и повторяются по кругу до нажатия «Остановить».
Режимы сохраняются в `data/modes.json` и доступны после перезапуска сервера.
Старые сохранённые режимы, где команды содержали IP, мигрируют при загрузке:
IP из команды будет отброшен, и при запуске нужно будет выбрать лампу заново.

### Если что-то не работает

| Симптом | Что проверить и сделать |
| --- | --- |
| `setup.bat` сообщает, что Python не найден | Установите Python 3.10 или новее, при установке включите добавление Python в PATH, затем откройте новое окно и повторите запуск. |
| Сервер сразу закрывается или пишет `Address already in use` | Порт из `YEELIGHT_PORT` уже занят. Закройте другой сервер Yeelight либо укажите свободный порт в `.env`; затем используйте этот порт в адресе клиента и перезапустите сервер. |
| Сервер не запускается при `0.0.0.0` | Проверьте, что в `.env` задан `YEELIGHT_API_TOKEN`. Для доступа извне localhost токен обязателен. |
| Телефон не открывает `http://IP:8000` | Убедитесь, что сервер запущен, адрес взят с активного адаптера компьютера, порт совпадает с `YEELIGHT_PORT`, устройства в одной обычной Wi-Fi/LAN-сети, VPN выключен, а Windows Firewall разрешает Python в частной сети. Проверьте, что телефон не подключён к гостевой сети с изоляцией клиентов. |
| Страница открывается, но клиент показывает HTTP 401 | Токен в приложении должен в точности совпадать со значением `YEELIGHT_API_TOKEN` в корневом `.env`. После изменения `.env` перезапустите сервер и повторно сохраните подключение в клиенте. |
| Страница открывается, но клиент не видит лампы | В клиенте сначала выполните `discover`. Если поиск не находит лампу, включите управление по LAN в настройках лампы/приложения Yeelight (если модель поддерживает эту функцию), проверьте, что лампа и сервер в одной локальной сети, и попробуйте `add <IP>` с известным адресом лампы. |
| Лампа находится, но команда завершается ошибкой | Выполните `status <IP>`, проверьте IP и доступность лампы, отсутствие изоляции между Wi-Fi-клиентами и поддержку команд/режимов конкретной моделью. При смене IP повторите `discover` или `add` с новым адресом. |
| После перезапуска сервера список ламп пуст | Это ожидаемо для ламп, добавленных командами `discover`/`add`: они хранятся в памяти. Повторите поиск или заполните `YEELIGHT_BULBS` в `.env`. |
| Flet сообщает, что Android SDK не найден | Установите Android SDK через Android Studio, задайте `ANDROID_HOME`/`ANDROID_SDK_ROOT`, откройте новое окно терминала и проверьте `flet doctor` и `flutter doctor -v`. |
| APK не устанавливается | Убедитесь, что APK собран без ошибок и полностью скопирован. Для установки из файла разрешите установку из выбранного источника Android. Если уже установлена несовместимая версия, удаление приложения удалит сохранённые в нём адрес и токен. |

Если поиск ламп не работает, хотя управление по её IP работает, причиной может
быть блокировка широковещательного обнаружения роутером или сетью. В таком
случае используйте `add <IP>` и, чтобы адрес не менялся, настройте DHCP-
резервирование на роутере.

### Безопасность

Токен — это проверка доступа к API, а не шифрование: HTTP-трафик в этой версии
не зашифрован. Используйте сервер только в доверенной локальной сети. Не
создавайте переадресацию порта `8000` на роутере в интернет, не публикуйте
`.env` и не отправляйте токен посторонним. При подозрении на утечку замените
`YEELIGHT_API_TOKEN` в `.env` и перезапустите сервер; сохраните новый токен
также в мобильном клиенте.
