# Yeelight

Управление Yeelight через локальный сервер и адаптивный веб-интерфейс. FastAPI
обслуживает одновременно HTTP API и браузерный клиент; браузер отправляет
команды серверу, а сервер взаимодействует с лампами по LAN-протоколу Yeelight.
Клиентская часть не использует Python и не требует APK.

## Возможности

- Поиск, добавление, удаление и управление лампами.
- Веб-интерфейс для Windows, Android, iOS и других устройств с современным
  браузером.
- Настройка питания, яркости, цвета RGB и цветовой температуры.
- Консоль команд, сохранённые циклические режимы и готовые цветовые пресеты.
- Сохранение списка ламп и режимов между перезапусками.
- API-токен для доступа из локальной сети.

Лампа должна быть доступна серверу по Wi-Fi/LAN. Для модели
`yeelink.light.color1` добавлена экспериментальная настройка Wi-Fi через
miIO в режиме временной точки доступа; прочие модели этим способом не
настраиваются. После отправки настроек компьютер нужно подключить к той же
сети Wi-Fi, что и лампу, затем выполнить поиск. Для остальных моделей
используйте официальное приложение Yeelight.

## Установка

Требуется Python 3.10 или новее. В Windows запустите `setup.bat`: он создаст
виртуальное окружение `.venv`, при необходимости скопирует `.env.example` в
`.env` и установит проект с зависимостями.

Вручную в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item .env.example .env
```

`Copy-Item` нужен только если файла `.env` ещё нет. Не публикуйте `.env` и не
вставляйте в него значения секретов из других систем.

## Запуск

Для запуска сервера и открытия веб-интерфейса в браузере используйте:

```powershell
.\start-all.bat
```

Сервер по умолчанию доступен по адресу `http://127.0.0.1:8000`. Его можно
запустить отдельно командой:

```powershell
.\.venv\Scripts\python.exe -m yeelight_network.server
```

Затем откройте `http://127.0.0.1:8000` в браузере. Для доступа с телефона
настройте локальную сеть, как описано ниже.

## Настройки сервера

Параметры задаются в корневом `.env`:

| Переменная | Назначение |
| --- | --- |
| `YEELIGHT_HOST` | Адрес прослушивания; `0.0.0.0` включает доступ из LAN |
| `YEELIGHT_PORT` | Порт сервера, по умолчанию `8000` |
| `YEELIGHT_API_TOKEN` | Токен API; обязателен при прослушивании LAN |
| `YEELIGHT_BULBS` | Необязательный список начальных IP ламп через запятую |
| `YEELIGHT_POLL_INTERVAL_SECONDS` | Интервал проверки доступности ламп, по умолчанию `10` |
| `YEELIGHT_UNRESPONSIVE_TIMEOUT_SECONDS` | Время без ответа до удаления лампы из списка, по умолчанию `60` |
| `YEELIGHT_MODES_FILE` | Файл сохранения режимов, по умолчанию `data/modes.json` |
| `YEELIGHT_BULBS_FILE` | Файл сохранения ламп, по умолчанию `data/bulbs.json` |

Если изменить `.env`, перезапустите сервер.

## Доступ с телефона

1. Подключите телефон и компьютер с сервером к одной доверенной Wi-Fi/LAN-сети.
2. Запустите `configure-phone.bat`. Он выставит `YEELIGHT_HOST=0.0.0.0`,
   создаст случайный API-токен, если его ещё нет, и покажет адреса компьютера.
3. При запросе Windows Firewall разрешите Python только для частных сетей.
   При необходимости правило брандмауэра создаёт администратор Windows.
4. Перезапустите сервер через `start-all.bat` либо `start-server.bat`.
5. Откройте в браузере телефона LAN-адрес сервера, например
   `http://192.168.1.10:8000`.
6. В поле «API-токен» веб-страницы вставьте значение
   `YEELIGHT_API_TOKEN` из `.env`.

При локальном управлении с этого компьютера откройте
`http://127.0.0.1:8000` и так же укажите токен из `.env`; после ввода
список ламп и API загрузятся автоматически.

Токен хранится только в `sessionStorage` текущей вкладки и исчезает после её
закрытия. Это не защищённое хранилище; не используйте страницу в недоверенной
сети. По HTTP токен не шифруется, поэтому не открывайте порт сервера в
публичный интернет. Для удалённого доступа используйте VPN.

## Команды

В веб-консоль можно вводить команды по одной:

```text
discover
list
add 192.168.1.45
remove 192.168.1.45
status 192.168.1.45
on 192.168.1.45
off 192.168.1.45
toggle 192.168.1.45
brightness 192.168.1.45 60
color 192.168.1.45 51 170 255
color 192.168.1.45 #33aaff
temp 192.168.1.45 4000
```

Яркость задаётся от 1 до 100, температура — от 1700 до 6500 K, каналы RGB —
от 0 до 255. Также настройки доступны в карточке каждой лампы.

Режимы состоят из последовательности задач и запускаются для выбранного IP.
Они сохраняются в `data/modes.json`, не привязаны к адресу лампы и могут
редактироваться в браузере.

## Диагностика первоначальной настройки

В веб-интерфейсе есть форма первоначального подключения модели
`yeelink.light.color1`. Она доступна только при работе с браузера на том же
компьютере, что и сервер. SSID и пароль не записываются в файлы и не выводятся
в консоль приложения; отправка пароля происходит по локальному API и
шифрованному miIO-пакету. Лампа может перезапуститься и отключиться от точки
доступа, а ответ miIO не гарантирует присоединение к сети. Компьютер и лампа
должны затем оказаться в одной сети 2,4 ГГц с WPA2 для проверки через `discover`.
Не используйте эту функцию через удалённый HTTP-сервер.

`tools/provisioning_probe.py` — диагностическая утилита только для чтения.
Она не настраивает лампу, не принимает и не отправляет пароль Wi-Fi, не
переключает сеть и не включает LAN Control. На Windows команда
`--report` показывает версию ОС, сведения о Bluetooth и только видимые
Wi-Fi-сети с префиксом `yeelink-light-`; прочие названия сетей и BSSID в отчёт
не включаются:

```powershell
.\.venv\Scripts\python.exe tools\provisioning_probe.py --report
```

BLE-сканирование и чтение метаданных GATT доступны как отдельные
необязательные диагностические операции. Для них установите дополнительную
зависимость и выполните сканирование:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[diagnostics]"
.\.venv\Scripts\python.exe tools\provisioning_probe.py --ble-scan
.\.venv\Scripts\python.exe tools\provisioning_probe.py --gatt-address <BLE-адрес>
```

GATT-режим только перечисляет UUID сервисов, характеристики и их свойства —
значения не читаются и не записываются. Результат можно по желанию сохранить
через `--output path\to\report.json`; BLE-отчёт может содержать адреса и
рекламные данные устройств поблизости, поэтому сохраняйте его только локально
и при необходимости удалите после анализа. Обнаружение Bluetooth или сети
`yeelink-light-*` само по себе не подтверждает модель и возможность передать
ей настройки Wi-Fi.

Для уже обнаруженной по LAN лампы можно выполнить один адресный read-only
miIO handshake:

```powershell
.\.venv\Scripts\python.exe tools\provisioning_probe.py --miio-probe 10.0.0.25
```

Укажите текущий IP лампы. Команда не меняет настройки и показывает только,
ответило ли устройство и был ли токен в handshake; само значение токена не
выводится. Ответ не доказывает поддержку команды настройки Wi-Fi.
Для запроса только модели и версий прошивки (без изменения конфигурации)
используйте `--miio-info`:

```powershell
.\.venv\Scripts\python.exe tools\provisioning_probe.py --miio-info 192.168.13.1
```

## Включение LAN Control

Настройка Wi-Fi и включение LAN Control — два отдельных шага. Когда лампа уже
подключена к домашней сети, откройте интерфейс на компьютере, где запущен
сервер, введите текущий IP лампы в блоке «Включение LAN Control» и подтвердите
действие. Сервер проверяет модель `yeelink.light.color1`, получает miIO-токен
непосредственно от лампы через handshake и использует его только в памяти для
команды `set_ps` / `cfg_lan_ctrl`. Токен не показывается и не сохраняется.
Маршрут доступен только с loopback этого компьютера; включение не происходит
автоматически после настройки Wi-Fi.

Ответ miIO сам по себе не подтверждает работу LAN Control. После ответа
выполните отдельную read-only проверку из корня проекта:

```powershell
.\.venv\Scripts\python.exe tools\lan_control_probe.py 192.168.1.45
```

Замените адрес на текущий IP лампы. Успешный результат должен показывать
`"tcp_55443": "open"`, `"ssdp_1982": "found"` и `"get_prop": "ok"`.
Диагностика использует SSDP multicast `239.255.255.250:1982` и читает только
свойство питания командой `get_prop`; она не меняет состояние лампы. Если
miIO-handshake не вернул пригодный токен, включить LAN Control этим путём
нельзя: приложение сообщит об ошибке и не будет подставлять секрет или
извлекать его из аккаунта. API и LAN Control не открывайте в публичный интернет.

Реализация команды `set_developer_mode` в `python-miio` для Yeelight использует
`set_ps` с параметрами `["cfg_lan_ctrl", "1"]`. `python-miio` не является
зависимостью проекта; команда реализована в локальном miIO-адаптере и не
требует установки или входа в аккаунт.

## API и структура

- `yeelight_network/api.py` — FastAPI-маршруты, авторизация, статический
  веб-интерфейс, мониторинг и режимы.
- `yeelight_network/server.py` — конфигурация и запуск сервера.
- `yeelight_logic/controller.py` — команды Yeelight и хранение IP ламп.
- `yeelight_app/static/` — HTML, CSS и JavaScript веб-клиента.
- `yeelight_network_utils.py` — определение LAN-адресов.
- `configure_phone.py` — настройка доступа из локальной сети.

Основные маршруты: `/` (интерфейс), `/api/health`, `/api/bulbs`,
`/api/settings`, `/api/commands`, `/api/modes` и
`/api/provisioning/wifi`, `/api/provisioning/lan-control`. Маршрут включения
LAN Control требует loopback-доступа и защищённого API-маршрута, как и
настройка Wi-Fi. Защищённые маршруты принимают
токен в заголовке `X-API-Token`; он не передаётся в URL.
